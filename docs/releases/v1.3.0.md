# Firmware v1.3.0

The level now reads right the moment the unit wakes, and a unit can be tested and updated over Wi-Fi. The code was also tidied throughout, with no change in behaviour.

Updating from v1.2.0 keeps the unit's settings and its sensor calibration. A unit updating from an older version needs Settings, Advanced, Sensor calibration once, as described in v1.1.0.

## What is new

**Level view**
- The level reads right as soon as the screen comes back on. The motion sensor now runs whenever the unit is on, including while the screen is dark.
  - Before, the sensor stopped while the screen was dark and restarted from where it had been. A unit picked up and set down on a prop read 13 to 14° off when it came to rest, and took 6 to 8 s to come right.
  - Now it reads within 0.6° at rest, and within 0.2° by 1.5 s at most. A unit tilted 5° while dark reads within 0.25° at its first reading.
  - The level is also right at once after another tile, if the unit was moved meanwhile.
- A unit lying still no longer wakes itself. Only being moved wakes it.
- The cost: a dark unit draws more, an estimated 15 to 17 mA instead of 1 to 2 mA. That is about 10% of the cell over a match day with twelve 30-minute breaks. The power-off timer still switches the unit off after 5 hours dark by default.

**Dope**
- A tap on the dope card no longer moves the list.

**Wi-Fi and testing**
- Settings, Advanced has two switches: "USB remote control" (as before) and "Wi-Fi remote control" (off by default). With the Wi-Fi switch on, the remote control and the device tests work over the network. Anyone on that network can then send commands, so leave it off when you are done.
- The Wi-Fi page shows the unit's network name and address while it is connected.
- Every name the unit goes by carries the same 7-digit number: `HUD-<n>` for the Kestrel, `OWMC_<n>` while it is being set up (it was a different number before), and `owmc-<n>` on the network.

**Code**
- No compiler warnings, no dead code, the services no longer call the screens, and the source is in folders by role. The build fails on any new warning.

**Releases**
- Each release now carries its own update manifest (`manifest.json`), with the firmware's address on the release. Units do not use it yet: a later release makes them look for updates on GitHub.

## Updating a unit

Over Wi-Fi, from the repo on a computer on the unit's network, with this release's OTA package:

```bash
python scripts/ota_host.py --package OpenWeaponMountComputerFirmware-v1.3.0-ota.zip
```

Restart the unit: after its Wi-Fi connects it finds the update, and Settings shows "Update available" at the top. Units already on v1.3.0 are not offered it.

## Known limits

- Updates come over plain HTTP from a host on the local network and are not signed; the image's checksum rejects a damaged download. Run the host only on a network you trust.
- The update check compares major, minor and patch only: builds after v1.3.0 that are not tagged read as 1.3.0 and are not offered to a 1.3.0 unit (`--force` on the host offers them).
- The second update source, a central server, is a placeholder and not enabled.
- The Power page still offers 4.35 V and 4.4 V charge voltages. They are above the Vapcell T9's 4.20 V, so keep 4.2 V for that cell.
- Right after power-on, the level can read up to about 0.15° off while the sensor warms up; it settles within about 3 minutes.

## Files

- `OpenWeaponMountComputerFirmware-v1.3.0.bin`: the firmware (the image an update installs).
- `OpenWeaponMountComputerFirmware-v1.3.0-ota.zip`: the OTA package: the update's manifest (version v1.3.0 and the note the unit shows) and the firmware, served by `scripts/ota_host.py --package`.
- `manifest.json`: the same manifest, with the firmware's address on this release.
- `bootloader.bin`, `partition-table.bin`, `ota_data_initial.bin`: with the firmware, all a unit needs over USB.

Flashing over USB with esptool keeps the unit's settings (the settings partition is not written); the unit then starts from the first app slot:

```bash
python -m esptool --chip esp32s3 -p <port> write_flash --flash_mode dio --flash_freq 80m --flash_size 16MB 0x0 bootloader.bin 0x8000 partition-table.bin 0x10000 ota_data_initial.bin 0x320000 OpenWeaponMountComputerFirmware-v1.3.0.bin
```

# Firmware v1.4.0

A unit now finds new firmware by itself: once its Wi-Fi connects, it checks this project's latest GitHub release over a secured connection, and offers the update when there is a newer one.

Updating from v1.3.0 keeps the unit's settings and its sensor calibration. A unit updating from an older version needs Settings, Advanced, Sensor calibration once, as described in v1.1.0.

## What is new

**Updates**
- After its Wi-Fi connects at start-up, the unit looks for an update in two places, in order:
  1. a computer on the local network running `scripts/ota_host.py`, as before. If it answers, it decides, so a build can be tried on a unit before it is released;
  2. otherwise, the latest published release of this project on GitHub, over HTTPS with the certificate checked. The firmware is downloaded from that release over HTTPS too.
- When the release is newer than the unit's firmware, Settings shows "Update available" at the top, as before. Install downloads it, and Restart runs it. A download from GitHub takes about 40 seconds.
- Draft and pre-release versions on GitHub are never offered. The unit checks once per start, as before.
- The old placeholder update server is gone.

## Updating a unit

**Units on v1.3.0 or older** look only on the local network, so they need a computer for this one update. From the repo, on a computer on the unit's network, with this release's OTA package:

```bash
python scripts/ota_host.py --package OpenWeaponMountComputerFirmware-v1.4.0-ota.zip
```

Restart the unit: after its Wi-Fi connects it finds the update, and Settings shows "Update available" at the top.

**Units on v1.4.0** find the next release on GitHub by themselves. They only need Wi-Fi with internet access.

## Known limits

- Firmware images are not signed. A download from GitHub is protected by HTTPS, and the image's checksum rejects a damaged download. The local host (`ota_host.py`) serves over plain HTTP: run it only on a network you trust, because a unit takes its answer first.
- The update check compares major, minor and patch only: builds after v1.4.0 that are not tagged read as 1.4.0 and are not offered to a 1.4.0 unit (`--force` on the host offers them).
- An update that cannot start leaves the unit on its old firmware, but there is no automatic rollback after a bad update: a unit that cannot start its new firmware needs USB.
- The Power page still offers 4.35 V and 4.4 V charge voltages. They are above the Vapcell T9's 4.20 V, so keep 4.2 V for that cell.
- Right after power-on, the level can read up to about 0.15° off while the sensor warms up; it settles within about 3 minutes.

## Files

- `OpenWeaponMountComputerFirmware-v1.4.0.bin`: the firmware (the image an update installs).
- `OpenWeaponMountComputerFirmware-v1.4.0-ota.zip`: the OTA package: the update's manifest (version v1.4.0 and the note the unit shows) and the firmware, served by `scripts/ota_host.py --package`.
- `manifest.json`: the same manifest, with the firmware's address on this release. Units on v1.4.0 read it from the latest release.
- `bootloader.bin`, `partition-table.bin`, `ota_data_initial.bin`: with the firmware, all a unit needs over USB.

Flashing over USB with esptool keeps the unit's settings (the settings partition is not written); the unit then starts from the first app slot:

```bash
python -m esptool --chip esp32s3 -p <port> write_flash --flash_mode dio --flash_freq 80m --flash_size 16MB 0x0 bootloader.bin 0x8000 partition-table.bin 0x10000 ota_data_initial.bin 0x320000 OpenWeaponMountComputerFirmware-v1.4.0.bin
```

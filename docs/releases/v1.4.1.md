# Firmware v1.4.1

A unit on USB charges again. From a PC port or a phone charger, units barely charged: the charger reported charging, but next to no current reached the cell.

Updating from v1.2.0 or later keeps the unit's settings and its sensor calibration.

## What is new

**Charging**
- The charger cuts its current to keep the unit's supply (VSYS) above a set level, which was the chip's default of 4.7 V. On the boards built so far, USB arrives at about 4.6 V after the input diode, so the charger held the current back to almost nothing. The level is now 4.1 V.
- Measured on one unit, from a PC port: 0.43 A from USB, with the cell voltage rising, where before it stayed at 26% for a day.
- The current is still limited by the board's input, not by the charge current setting: 0.43 A in all from that 5 V port, part of which runs the unit.

**Remote control**
- `pmic regs`: the charger's registers, raw and decoded. It reads only. `pmic tdie on|off` switches the chip's die temperature reading.

## Updating a unit

**Units on v1.4.0** find this release on GitHub by themselves, after their Wi-Fi connects at start-up: Settings shows "Update available" at the top.

**Units on v1.3.0 or older** look only on the local network, so they need a computer for this one update. From the repo, on a computer on the unit's network, with this release's OTA package:

```bash
python scripts/ota_host.py --package OpenWeaponMountComputerFirmware-v1.4.1-ota.zip
```

Restart the unit: after its Wi-Fi connects it finds the update.

## Known limits

- Check Settings, Advanced, Charge voltage on each unit: keep 4.2 V for the Vapcell T9. The page still offers 4.35 V and 4.4 V, which overcharge it, and a unit keeps whatever was chosen before.
- While on USB, the battery percentage rises faster than the cell really charges: it follows the cell's voltage under charge. Read the cell's voltage instead (Settings, Power).
- A charge has not yet been watched through to the end (the charger's "done") on a unit with this release.
- Firmware images are not signed. A download from GitHub is protected by HTTPS, and the image's checksum rejects a damaged download. The local host (`ota_host.py`) serves over plain HTTP: run it only on a network you trust, because a unit takes its answer first.
- The update check compares major, minor and patch only: builds after v1.4.1 that are not tagged read as 1.4.1 and are not offered to a 1.4.1 unit (`--force` on the host offers them).
- There is no automatic rollback after a bad update: a unit that cannot start its new firmware needs USB.
- Right after power-on, the level can read up to about 0.15° off while the sensor warms up; it settles within about 3 minutes.

## Files

- `OpenWeaponMountComputerFirmware-v1.4.1.bin`: the firmware (the image an update installs).
- `OpenWeaponMountComputerFirmware-v1.4.1-ota.zip`: the OTA package: the update's manifest (version v1.4.1 and the note the unit shows) and the firmware, served by `scripts/ota_host.py --package`.
- `manifest.json`: the same manifest, with the firmware's address on this release. Units on v1.4.0 or later read it from the latest release.
- `bootloader.bin`, `partition-table.bin`, `ota_data_initial.bin`: with the firmware, all a unit needs over USB.

Flashing over USB with esptool keeps the unit's settings (the settings partition is not written); the unit then starts from the first app slot:

```bash
python -m esptool --chip esp32s3 -p <port> write_flash --flash_mode dio --flash_freq 80m --flash_size 16MB 0x0 bootloader.bin 0x8000 partition-table.bin 0x10000 ota_data_initial.bin 0x320000 OpenWeaponMountComputerFirmware-v1.4.1.bin
```
